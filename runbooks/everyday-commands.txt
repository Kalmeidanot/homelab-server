SAMBA RECYCLE PROTECTION

Media and Archive recycle are active and tested. SMB deletes go to .recycle/%U
inside each share, preserving the relative directory tree. For kaian, inspect
only these recycle trees (run on the server as kaian):

du -sh /srv/storage/media/.recycle /srv/storage/archive/.recycle
find /srv/storage/media/.recycle/kaian /srv/storage/archive/.recycle/kaian -type f -print
stat -c '%a %U:%G %n' /srv/storage/media/.recycle /srv/storage/media/.recycle/kaian /srv/storage/archive/.recycle /srv/storage/archive/.recycle/kaian

Expected directory metadata: 700 kaian:kaian. Preserve both .recycle roots.
These checks stay within the recycle areas; do not expand them to archive/merged
or its excluded hidden tree. Recycled files consume space until deliberately
removed. No broad cleanup/delete command is provided here.

Read-only Samba configuration and connection checks (run on the server):

testparm -s
systemctl is-active smbd
sudo smbstatus

Expected: Loaded services file OK; smbd active. testparm checks configuration
syntax, not end-to-end recycle behavior. An established SMB share connection may
retain its previous configuration after smbd reload. After finishing transfers,
close all SMB connections from the client, check sessions/locked files with
smbstatus, and reconnect before testing new share settings. Media passed after
this reconnect; the first test on an old connection did not recycle the file.

Recycle is not backup or a general Linux filesystem recycle bin. It covers SMB
deletes, not rm, application/container deletion (including Immich), disk failure,
corruption, loss of the WD My Book, or sufficiently privileged malicious access.
Files stay on the same physical disk. Deleting inside .recycle is not recursively
recycled because recycle:exclude_dir = .recycle. Large movies are eligible:
no size limits or file exclusions were configured.
See changes/2026-09-17-enable-samba-recycle-bin.md for the full tests and recovery.

Refreshes the available-package list. It does not install upgrades.

even while server networking and apt work normally. Do not change working network
configuration solely to fix this Cockpit/PackageKit/NetworkManager false-offline
behavior. It is a low-priority backlog item.

Ubuntu phased updates may remain listed after a successful upgrade. Do not force
them merely to make the list empty; allow them to roll out normally.
