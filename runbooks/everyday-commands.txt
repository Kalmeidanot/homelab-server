============================================================
1. CONNECT TO THE SERVER FROM WINDOWS
============================================================

ssh kaian@10.0.0.6

Run from Windows Terminal or PowerShell. Connects to the Lenovo over the home
network. Enter the Ubuntu password when asked.

exit

Run inside SSH. Disconnects safely. It does not shut down the server.

ping 10.0.0.6

Run from Windows for a quick home-network reachability test. Press Ctrl+C to stop.

============================================================
3. TAILSCALE / REMOTE ACCESS
============================================================

Run these commands on the server inside SSH.

tailscale status

Shows devices visible on the private Tailscale network.

tailscale ip -4

Shows the server's Tailscale IPv4.
Expected current value: 100.83.35.13

systemctl is-active tailscaled

Expected output: active

Tailscale is configured to start automatically. Normally, do NOT run
"sudo tailscale up" again.

Remote Jellyfin access has been successfully tested over mobile data. The client
device must normally be connected to the same Tailscale network. A random TV
outside the house cannot currently use the Tailscale address unless that TV or
device also supports Tailscale. Universal Jellyfin access from arbitrary TVs and
devices is a future backlog item.

============================================================
7. CHECK WD MY BOOK TEMPERATURE
============================================================

Run on the server inside SSH.

sudo smartctl -A /dev/sda | grep Temperature_Celsius

Reads the WD My Book hard-drive temperature, not the Lenovo CPU temperature.
Enter the Ubuntu password if asked.

Example output ending:
... 47 (Min/Max 23/54)

47 = current HDD temperature
23 = lowest recorded temperature
54 = highest recorded temperature

9. JELLYFIN / DOCKER
============================================================

Run these commands on the server inside SSH.

sudo docker ps

Shows running Docker containers.

cd ~/nas-admin/compose/jellyfin

sudo docker compose ps

Shows Jellyfin container status specifically.

sudo docker logs --tail 50 jellyfin

Shows the newest 50 Jellyfin log lines.

Before the next two Compose commands, first run:

cd ~/nas-admin/compose/jellyfin

sudo docker compose restart jellyfin

Restarts only Jellyfin.
WARNING: Active Jellyfin viewers will be disconnected.

sudo docker compose up -d

Starts Jellyfin from the Compose configuration if it is stopped. "-d" means
detached/background mode.

============================================================
14. SAFE SERVER SHUTDOWN
============================================================

Before shutdown, check that:
- no Samba or other file transfer is running
- nobody is actively using Jellyfin
- no disk test is running
- no important installation or update is running

Run on the server inside SSH only after those checks.

sudo shutdown -h now

Safely shuts down the Lenovo. Wait until the machine is fully powered off before
removing power.

============================================================
15. SAFE REBOOT
============================================================

NO FILE TRANSFER should be running first. Also check that nobody is actively
using Jellyfin.

Run on the server inside SSH.

sudo reboot

Safely restarts Ubuntu. This temporarily stops Jellyfin, Samba/file transfers,
Cockpit, SSH, Docker containers, and Tailscale.

After roughly 1-2 minutes, reconnect from Windows Terminal or PowerShell:

ssh kaian@10.0.0.6

============================================================
16. CHECK FOR UBUNTU UPDATES
============================================================

Run these commands on the server inside SSH.

sudo apt update

Refreshes the available-package list. It does not install upgrades.

apt list --upgradable

Shows available upgrades.

sudo apt upgrade

Installs normal available package upgrades. Perform upgrades deliberately rather
than blindly during other server changes.

APT is currently the authoritative update method. Cockpit itself is operational,
but its Software Updates page may report "Cannot refresh cache whilst offline"
even while server networking and apt work normally. Do not change working network
configuration solely to fix this Cockpit/PackageKit/NetworkManager false-offline
behavior. It is a low-priority backlog item.

Ubuntu phased updates may remain listed after a successful upgrade. Do not force
them merely to make the list empty; allow them to roll out normally.

============================================================
19. SAFETY RULES
============================================================

STOP AND CHECK WHETHER A FILE TRANSFER IS CURRENTLY RUNNING before doing anything
involving:
- reboot
- shutdown
- networking
- Tailscale networking changes
- Samba restart
- disk mount or unmount
- filesystem permissions
- Docker networking
- storage changes

Also check whether someone is actively watching Jellyfin before:
- restarting Jellyfin
- restarting Docker
- rebooting or shutting down the server

When unsure, stop and inspect first. Do not paste commands you do not understand,
and do not put passwords, API keys, tokens, private keys, recovery codes,
encryption keys, or Codex authentication contents into documentation or Git.
